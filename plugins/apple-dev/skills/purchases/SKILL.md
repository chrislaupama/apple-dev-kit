# Purchases

- A StoreKit configuration (.storekit) file lets the app load and buy its products locally, with no App Store Connect setup. Xcode applies the file a scheme launches with when it runs the app from Xcode (Simulator or device), but not when the app is launched with `simctl`/`xc preview`, nor in TestFlight or the App Store, so use one only for local testing from Xcode. In a Project.json project, set the app target's `scheme.storeKitConfiguration` to the file's path relative to the project folder. In an Xcode project, add `<StoreKitConfigurationFileReference identifier="…"/>` inside the scheme's LaunchAction, with the path relative to the workspace: `../../` reaches the folder containing a project's .xcodeproj from a scheme inside it. Product IDs in the file must match the ones the app requests.
- For in-app purchases and subscriptions that ship, define the real products in App Store Connect via the project's appStoreConnect/ listing files (the app-store-connect skill covers this). As part of that setup, make sure the bundle identifier in Project.json matches the App Store Connect app's bundle ID so builds can load the real products — connecting the app record rewrites a scaffold placeholder automatically; only a customized identifier needs a manual update. If the project uses RevenueCat, its Test Store can simulate purchases for testing without any App Store Connect products — the revenuecat-testing-setup skill covers the setup. Real sandbox purchases can't complete in the built-in simulator, but they work when the user runs the app on their device with Run on… or via TestFlight and signs in with a Sandbox Apple Account.
- Products reach App Review only with an app build: Apple reviews an app's first in-app purchase or subscription together with a binary and rejects a build that references products it hasn't reviewed. When submitting the app version (see the app-store-connect skill; `asc review doctor` lists what's missing), add every product awaiting review to the same submission, and get products to Ready to Submit (not Missing Metadata) before submitting rather than submitting products separately.
